# Project Brief: Плагин DistDoc (JSON Schema Introspection Engine для Trino)

## 1. Бизнес-контекст и проблематика
В современных хранилищах данных (DWH / Data Lake) на базе объектных хранилищ (S3 / MinIO) объемы слабоструктурированных 
данных в формате JSON растут экспоненциально. Главная проблема таких данных — их скрытый полиморфизм 
(меняющиеся на лету типы, разорванные компоненты дат, пустые или вложенные структуры), 
поставляемый upstream-системами без предварительного уведомления (Schema Drift).

Существующие стандартные решения парсинга JSON в SQL-движках требуют явного указания жестких путей. 
Если схема меняется, конвейеры данных (Data Pipelines) ломаются, вызывая простои в аналитической отчетности.

## 2. Бизнес-цель
Создать высокопроизводительный распределенный механизм интроспекции («рентген для данных»), 
который за один проход по терабайтной сырой таблице выстраивает полную карту фактически присутствующих JSONPath-путей, 
определяет результирующие типы данных и подсвечивает структурные аномалии для dbt (Data Build Tool). 
На основе этого отчета dbt-шаблонизатор автоматически генерирует стабильный staging-слой SQL-моделей.

## 3. Функциональные требования
* **Полная интроспекция документов:** Функция должна обнаруживать абсолютно все ключи, вложенные объекты и массивы на любой глубине вложенности.
* **Автоматическое деэкранирование под-документов:** Если внутри текстового поля находится сериализованная JSON-строка 
  (частый кейс для CDC-логов из Kafka), движок должен автоматически распознать её, деэкранировать и 
  продолжить построение схемы для вложенных полей как для единого документа.
* **Выявление аномалий для dbt:**
    * **Пустые массивы:** Идентификация списков, не содержащих элементов, для корректного объявления типов в dbt.
    * **Однородные текстовые списки:** Маркировка плоских массивов строк для оптимизации их развертки (flatten) в dbt.
    * **Частицы дат:** Обнаружение массивов, состоящих строго из 3-х цифровых компонентов, 
      представляющих разорванную дату (ГГГГ-ММ-ДД), для автоматической генерации макросов конкатенации и явного приведения типов (`CAST AS DATE`).
* **Полиморфное сведение типов:** При обнаружении разных типов данных на одном и том же пути (например, `INTEGER` и `VARCHAR`), 
  итоговый тип должен сводиться к `VARCHAR` для предотвращения потери данных (`Data Loss`) при кодогенерации схем таблиц.

## 4. Границы системы (Out of Scope)
* Система не занимается физической трансформацией или очисткой данных — она только собирает метаданные и генерирует отчет.
* Система не строит визуальные диаграммы — выходным форматом является строго структурированный JSON-документ метаданных, 
  оптимизированный для автоматического чтения шаблонизатором dbt.

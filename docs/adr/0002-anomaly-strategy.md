# 0002 Стратегия детекции аномалий

Status: accepted
Date: 2026-09-08

## Context and Problem Statement
Бизнес-правила dbt (валидация дат, регулярные выражения, разворачивание массивов)
эволюционируют независимо от ядра парсера. Ядро стриминг-парсера не должно знать
конкретные бизнес-правила, иначе каждое новое правило потребует правки парсера.

## Decision
Логика анализа массивов вынесена в интерфейс-стратегию `AnomalyDetector`. Парсер по
завершении обработки массива передаёт неизменяемый DTO `ArrayContext` (снимок данных
массива) в этот интерфейс; решение о маркировке принимает стратегия.

> **Уточнение (ADR-0006, 2026-09-27).** Стратегия фиксирует аномалию вызовом
> `PathMetrics.markAnomaly(name)` — только установка, без сброса (аномалия монотонна);
> в rx-data 2.0 она записывается ключом в `anomalies` (docs/contracts/rx-data-contract.md,
> раздел 3). Прежний `setAnomaly(name, boolean)` удалён.

## Consequences
- Ядро стриминга не знает бизнес-правил dbt — зависимости направлены от стратегии к ядру.
- Новые флаги аномалий (dateasarray, emptyarray, stringsasarray и будущие) добавляются
  новой реализацией стратегии без правки парсера.
- Паттерн 3 из docs/patterns/plugin.md зафиксирован как архитектурное решение.

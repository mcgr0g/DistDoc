# 0008 Неоднородная форма пути: аномалия вместо узлов объектов (rx-data 3.0)

Status: accepted
Date: 2026-10-05

Заменяет в [0007](0007-object-nodes-structural-polymorphism.md) решение об узлах `OBJECT` на каждом объекте;
остальное в 0007 (major 3.0, правило «у элемента массива объекта нет», `is_array_empty` по числу элементов) действует.

## Context and Problem Statement

0007 ввёл узел `type: "OBJECT"` на каждом объекте. Реализация и обсуждение показали:

- узлы для чистых объектов (`$.profile`, `$._id`, `$.version`) — шум в каждом отчёте: генератор их пропускает, потребителю они не нужны;
- BSON-обёртки (`$oid`, `$date`, `$numberLong`, `$binary`) — не объекты, а запись скаляра; узел `$._id` вводил в заблуждение,
  а случай «id и на `_id`, и на `_id.$oid`» от этого не решался;
- нужна явная, трассируемая отметка неоднородности («здесь на одном пути разные формы»), а не вывод по соседним путям;
- состояние воркеров хранит только свёрнутый `type`: форма «объект», увиденная воркером вместе со скаляром, теряется при слиянии.

## Decision

- Чистые объекты записи не имеют (как в 2.0). Массив — запись `P[*]`, суффикс — достаточный признак массива.
- Формы пути `P`: `SCALAR`, `OBJECT`, `JSON_OBJECT` (объект внутри JSON-строки), `ARRAY` (есть `P[*]`). Если форм ≥ 2 — аномалия
  **`is_polymorphic_structure`** на записи `P`; запись существует только в этом случае (у чистого объекта в паре с массивом тоже). `trace` аномалии —
  по формам, элементы несут `form`.
- BSON-обёртка (первый ключ объекта начинается с `$`) — не объект и не форма `OBJECT`.
- Jsonstring: `is_json_string` (путь строки — `VARCHAR`), `has_non_json_strings` (рядом есть обычные строки; генератор downstream-модель не строит —
  без `try`). Текст, лишь похожий на JSON (`[TEST]`, `{abc}`), — обычная строка и не оставляет путей (валидирующий проход до рабочего).
- Все три аномалии **вычисляются при сборке отчёта** из множества типов пути (шаблон `is_polymorphic_format`); состояние воркеров передаёт
  `types` (набор внутренних типов, включая `OBJECT`, `JSON_STRING`, `JSON_OBJECT`) и `type_trace` вместо свёрнутого `type`.
- Ограничение: содержимое JSON-строки-массива и нативный массив на одном пути неразличимы (оба `P[*]`).

## Consequences

- Контракт `rx-data-contract.md` (разделы 2, 2b, 3, 4, переход 2.0 → 3.0) и схема (`traceItem.form`) переписаны; версия остаётся 3.0 (нигде не использовалась).
- Whitelist состояния: поле `type` заменено на `types`, добавлен `type_trace`; воркеры другой версии плагина пропускаются целиком паттерном 5.
- Матрица: узлы `OBJECT` удалены из базовой записи, ось `obj_` пересчитана, добавлены `obj_json_*` и `obj_bson_id_forms` (`fixture-matrix.md`).
- Генератор: полиморфность определяется по `is_polymorphic_structure`; `_id`/`$oid` сводятся `coalesce`; ограничения jsonstring записаны в `local/generator/generation.md`.

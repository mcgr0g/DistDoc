# Форматы значений (`observed_formats`)

Актуальный справочник распознавания написаний дат плагином: словарь, правила, таблица
примеров. Мотивы и отклонённые варианты — [ADR-0006](../adr/0006-format-detection.md)
(читать только если нужен ответ «почему так»). Форма отчёта —
[rx-data-contract.md](rx-data-contract.md).

Код: `formats/ValueFormat`, `formats/FormatDetector`, `config/FormatSettings`,
тесты — `FormatDetectorTest` (таблицы раздела 6 один в один).

## 1. Словарь

Закрытый enum `ValueFormat`. **Порядок объявления — контракт**: приоритет
SQL-подстановок генератора и порядок `observed_formats` в отчёте.

| № | Формат | Физический вход | Написание |
|---|---|---|---|
| 1 | `DATE_ONLY` | `VARCHAR` | `YYYY-MM-DD` |
| 2 | `LOCAL_DATETIME` | `VARCHAR` | `YYYY-MM-DDTHH:MM:SS[.f{1,9}]` |
| 3 | `OFFSET_DATETIME` | `VARCHAR` | то же + `±HH:MM` |
| 4 | `UTC_DATETIME` | `VARCHAR` | то же + `Z` |
| 5 | `UNIX_SECONDS` | `INTEGER`, `DOUBLE` | секунды от эпохи, только при контексте |
| 6 | `UNIX_MILLIS` | `INTEGER`, `VARCHAR` под `$numberLong` | миллисекунды от эпохи, только при контексте |

Формат фиксирует **написание**, а не момент времени: `+00:00` — `OFFSET_DATETIME`,
`Z` — `UTC_DATETIME`. Словарь версионируется вместе с плагином (`schema_version`):
новый формат — minor, изменение семантики существующего — major.

## 2. Строки

Строковые даты **не требуют контекста пути**: написание самоописательно, формат
доказывается формой значения и календарём.

1. Длина 10 (`DATE_ONLY`) или 19–35 (datetime); остальные строки отсекаются сразу.
2. Посимвольно: цифры и разделители `-`, `T`, `:` на своих позициях; дробь — `.` + 1–9
   цифр; суффикс — пусто (`LOCAL_DATETIME`), `Z` (`UTC_DATETIME`), `±HH:MM` (`OFFSET_DATETIME`).
3. Календарь: месяц `01–12`, день с учётом високосности, час `00–23`, минута и секунда
   `00–59`, `|offset| ≤ 18:00`.

Без regex, `java.time`, исключений и аллокаций. Строка, распарсенная как вложенный
JSON (jsonstring), форматом не проверяется — её скаляры проверяются на своих путях.

Не поддерживаются (формат не присваивается, ошибкой не считается): пробел вместо `T`,
строчные `t`/`z`, время без секунд, offset `+0300`/`+03`, год вне `0000–9999`,
ISO week/ordinal, `24:00:00`.

## 3. Числа

Число само по себе датой не является (`1784769300` — и дата, и счётчик), поэтому нужен
контекст:

1. **BSON `$date`** — значение в `$date` или `$date.$numberLong` всегда `UNIX_MILLIS`.
   Под `$numberLong` принимается и число, и цифровая строка (canonical Extended JSON:
   `{"$date":{"$numberLong":"1784769300000"}}`, физический тип `VARCHAR`).
2. **Path hint** (раздел 3.1).
3. Без контекста числовой формат не присваивается никогда.

Единица на пути с hint: `INTEGER` `|v| ≥ 1e11` → `UNIX_MILLIS`, иначе `UNIX_SECONDS`;
`DOUBLE` `|v| < 1e11` → `UNIX_SECONDS`, иначе без формата; `DOUBLE` внутри `$date` и
значения вне `long` — без формата. Отрицательные значения (до 1970) поддерживаются.

**Слепая зона:** millis из диапазона ≈ 1966-10 … 1973-03 распознаются как seconds.

### 3.1. Path hints

Секция `[format]` в `src/main/resources/app-config.toml`, пресет `["_at", "_utc"]`;
env `DISTDOC_FORMAT_PATH_HINTS` (CSV) полностью заменяет пресет.

- Сравнивается **последний значимый слог** пути: справа налево, пропуская `$date`,
  `$numberLong`, `$oid` и `[*]` (`$.created_at.$date.$numberLong` → `created_at`).
- Совпадение — `endsWith` с учётом регистра.
- `createdAt`, `birth_date` контекста не дают (включаются через env);
  счётчик в поле `*_at` даст ложный `UNIX_SECONDS`.
- Hints действуют только на числа.

## 4. Путь формата (scalar-leaf)

- Формат пишется на путь доказавшего скаляра и не поднимается к родителю
  (`$.created_at.$date.$numberLong`, а не `$.created_at`).
- Элементы массива — на путь массива `$.x[*]`; пустой массив форматов не даёт.
- Скаляр и массив на одном поле — два пути: `$.birth_date` и `$.birth_date[*]`.
- `BOOLEAN`, `null`, объекты форматов не имеют.

## 5. `observed_formats` и `is_polymorphic_format`

- 0 форматов — ключа нет; 1 формат — список из одного элемента; ≥ 2 — список и аномалия
  `is_polymorphic_format` (вычисляется и тогда, когда форматы видели разные воркеры).
- Только positive evidence: не гарантия для каждой строки; обычная строка формат не
  добавляет и не удаляет. Генератор всегда применяет `TRY_CAST`/fallback.
- Каждый элемент enum — отдельный формат для полиморфизма. Промоушен
  `INTEGER`+`DOUBLE` аномалией формата не является.

## 6. Таблица примеров

Источник table-driven тестов `FormatDetectorTest`. «Контекст»: `—` — путь без hint,
`hint` — последний значимый слог оканчивается на `_at`/`_utc`, `$date` — значение внутри `$date`.

### 6.1. Строки

| Вход | Ожидание | Что проверяет |
|---|---|---|
| `2026-07-23` | `DATE_ONLY` | базовый positive |
| `2024-02-29` | `DATE_ONLY` | високосный год |
| `2000-02-29` | `DATE_ONLY` | високосный вековой (`%400`) |
| `1900-02-29` | `null` | невисокосный вековой (`%100`) |
| `2025-02-29` | `null` | невисокосный год |
| `2026-02-30` | `null` | несуществующий день |
| `2026-04-31` | `null` | 30-дневный месяц |
| `2026-00-10`, `2026-13-10` | `null` | месяц вне `01–12` |
| `2026-7-23` | `null` | длина 9, нет ведущего нуля |
| `20260723` | `null` | basic ISO без разделителей |
| `2026/07/23` | `null` | чужой разделитель |
| `1990` | `null` | частица даты (`birth_date[*]`) |
| `2026-07-23T01:15:00` | `LOCAL_DATETIME` | базовый positive |
| `2026-07-23T00:00:00`, `2026-07-23T23:59:59` | `LOCAL_DATETIME` | границы времени |
| `2026-07-23T01:15:00.1`, `…00.123`, `…00.123456789` | `LOCAL_DATETIME` | дробь 1/3/9 цифр |
| `2026-07-23T01:15:00.` | `null` | точка без цифр |
| `2026-07-23T01:15:00.1234567890` | `null` | дробь 10 цифр |
| `2026-07-23T24:00:00` | `null` | час 24 |
| `2026-07-23T01:60:00`, `…T01:15:60` | `null` | минута/секунда 60 |
| `2026-13-23T01:15:00` | `null` | календарь в datetime |
| `2026-07-23 01:15:00` | `null` | пробел вместо `T` |
| `2026-07-23t01:15:00` | `null` | строчная `t` |
| `2026-07-23T01:15` | `null` | время без секунд |
| `2026-07-23T01:15:00+03:00` | `OFFSET_DATETIME` | базовый positive |
| `2026-07-23T01:15:00-05:30` | `OFFSET_DATETIME` | отрицательный offset |
| `2026-07-23T01:15:00+00:00` | `OFFSET_DATETIME` | нулевой offset ≠ `Z` |
| `2026-07-23T01:15:00+18:00`, `…-18:00` | `OFFSET_DATETIME` | граница offset |
| `2026-07-23T01:15:00+18:30` | `null` | `\|offset\|` > 18:00 |
| `2026-07-23T01:15:00+99:00`, `…+03:60` | `null` | offset вне диапазона |
| `2026-07-23T01:15:00+0300`, `…+03` | `null` | offset без `:` / без минут |
| `2026-07-23T01:15:00.5+03:00` | `OFFSET_DATETIME` | дробь + offset |
| `2026-07-23T01:15:00Z` | `UTC_DATETIME` | базовый positive |
| `2026-07-23T01:15:00.123Z` | `UTC_DATETIME` | дробь + `Z` |
| `2026-07-23T24:00:00Z` | `null` | час 24 |
| `2026-07-23T01:15:00z` | `null` | строчная `z` |
| `2026-07-23T01:15:00+00:00Z` | `null` | двойной суффикс |
| `""`, `deal`, `Mozilla`, `sp-0000000001` | `null` | обычные строки |
| `60b8d29f1a4c8b0000000001` | `null` | `$oid` (длина 24) |

| Вход | Физический тип | Контекст | Ожидание | Что проверяет |
|---|---|---|---|---|
| `1784769300` | `INTEGER` | hint | `UNIX_SECONDS` | базовый seconds |
| `1784769300000` | `INTEGER` | hint | `UNIX_MILLIS` | базовый millis |
| `1784769300` | `INTEGER` | — | `null` | id/счётчик без контекста |
| `1784769300000` | `INTEGER` | — | `null` | millis без контекста |
| `-86400` | `INTEGER` | hint | `UNIX_SECONDS` | 1969-12-31 |
| `-1262304000` | `INTEGER` | hint | `UNIX_SECONDS` | 1930-01-01, до эпохи |
| `0` | `INTEGER` | hint | `UNIX_SECONDS` | эпоха |
| `99999999999` | `INTEGER` | hint | `UNIX_SECONDS` | граница `< 1e11` |
| `100000000000` | `INTEGER` | hint | `UNIX_MILLIS` | граница `≥ 1e11` |
| `-100000000000` | `INTEGER` | hint | `UNIX_MILLIS` | граница с минусом |
| `31536000000` | `INTEGER` | hint | `UNIX_SECONDS` | **слепая зона**: это millis 1971-01-01 |
| `1784769300.5` | `DOUBLE` | hint | `UNIX_SECONDS` | дробные секунды |
| `1784769300000.0` | `DOUBLE` | hint | `null` | дробные millis не поддержаны |
| `4.5` | `DOUBLE` | — | `null` | рейтинг/деньги |
| `12345`, `7`, `2` | `INTEGER` | — | `null` | счётчик, `$numberLong` версии, `@version` |
| `1784769300000` | `INTEGER` | `$date` | `UNIX_MILLIS` | legacy `{"$date": N}` |
| `1784769300000` | `INTEGER` | `$date.$numberLong` | `UNIX_MILLIS` | число под `$numberLong` |
| `"1784769300000"` | `VARCHAR` | `$date.$numberLong` | `UNIX_MILLIS` | canonical Extended JSON |
| `"-86400000"` | `VARCHAR` | `$date.$numberLong` | `UNIX_MILLIS` | отрицательный canonical |
| `1784769300` | `INTEGER` | `$date` | `UNIX_MILLIS` | `$date` всегда millis, порог не применяется |
| `"1784769300000"` | `VARCHAR` | hint, `$.updated_at.$numberLong` | `UNIX_MILLIS` | цифровая строка под `$numberLong` + hint |
| `"1784769300000"` | `VARCHAR` | hint, без `$numberLong` | `null` | цифровая строка вне `$numberLong` — не число |
| `"2026-07-23T01:15:00Z"` | `VARCHAR` | `$date` | `UTC_DATETIME` | relaxed Extended JSON |
| `true`, `null` | — | hint | `null` | не скаляры формата |

### 6.3. Path hints

| Путь | Последний значимый слог | Hint (`_at`, `_utc`) |
|---|---|---|
| `$.created_at` | `created_at` | да |
| `$.created_at.$date.$numberLong` | `created_at` | да (но контекст — `$date`) |
| `$.events_at[*]` | `events_at` | да |
| `$.meta.sync_utc` | `sync_utc` | да |
| `$.createdAt` | `createdAt` | нет |
| `$.created_AT` | `created_AT` | нет (регистр) |
| `$.birth_date` | `birth_date` | нет |
| `$.version.$numberLong` | `version` | нет |
| `$.format` | `format` | нет (`endsWith("_at")` ложно) |
| `$.chat` | `chat` | нет |

Env `DISTDOC_FORMAT_PATH_HINTS`: `null` → пресет; `""`/`"  "` → пресет;
`"_ts, ,Date"` → `["_ts", "Date"]`.
